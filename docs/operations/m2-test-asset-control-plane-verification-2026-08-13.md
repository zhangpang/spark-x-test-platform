## 9. 验证中发现并修复的根因

首次 API 端到端验证发现，用例 v1 创建返回 HTTP 500。数据库中用例和版本已经插入，但 `current_draft_version_id` 为空。

根因是用例、数据集和公共步骤的首次创建使用单条 PostgreSQL 数据修改 CTE，在同一语句中尝试更新本语句刚插入的资源行。各修改子语句使用同一快照，最后的 `UPDATE` 无法看到刚插入的资源行，返回空结果并触发 TypeError。

提交 `5198f5a2e5474daf96a359bebe90e12686d312e0` 增加真实数据库事务，将“资源行、v1、当前版本指针、审计”改为同一事务内的顺序语句，并同时覆盖用例、数据集和公共步骤。修复后完整端到端回归通过。

测试过程中产生的两个中断诊断系统已标记为 `archived`；故障产生的唯一空草稿指针已按其最新版本修复，数据库中不再存在“已有版本但当前草稿指针为空”的用例。
