# 星火 Agent 首批回归案例目录

本文定义 MVP 的 32 个 P0/P1 场景。正式实现时，每个场景可以包含多个数据集迭代，但案例标识保持稳定。

## 1. 聊天（5）

| ID | 优先级 | 场景 | 核心判定 |
| --- | --- | --- | --- |
| CHAT-001 | P0 | 新会话与流式回答 | 会话创建、首段响应、流结束、消息持久化一致 |
| CHAT-002 | P0 | 同一会话上下文续接 | 第二轮能引用第一轮已知事实，不串入其他会话 |
| CHAT-003 | P1 | 用户停止生成 | 流被终止、状态可续接、不会追加幽灵消息 |
| CHAT-004 | P1 | Provider短暂失败后的明确重试 | 首次错误可见，重试产生独立尝试且消息不重复 |
| CHAT-005 | P1 | 长上下文压缩后续接 | 压缩前后关键事实保留，工具状态和会话游标连续 |

## 2. 工具调用（5）

| ID | 优先级 | 场景 | 核心判定 |
| --- | --- | --- | --- |
| TOOL-001 | P0 | 当前范围内工具发现 | 只向模型暴露当前会话允许的工具 |
| TOOL-002 | P0 | 工具选择与参数绑定 | 工具名正确，系统注入参数和模型参数层级正确 |
| TOOL-003 | P0 | 工具结果进入最终回答 | 工具只调用预期次数，关键结果无错误映射 |
| TOOL-004 | P1 | 工具失败与恢复 | 错误分类、用户提示和后续工具循环符合协议 |
| TOOL-005 | P0 | 禁止的工具与写操作 | 无权限工具不暴露、不调用、不产生副作用 |

## 3. 知识库维护与使用（6）

| ID | 优先级 | 场景 | 核心判定 |
| --- | --- | --- | --- |
| KB-001 | P0 | 创建、上传、解析和索引就绪 | 状态按顺序转换，文件可检索，重复提交幂等 |
| KB-002 | P0 | 会话绑定范围 | 只检索已绑定知识库，系统注入范围正确 |
| KB-003 | P0 | B2C订单文件准确检索 | 必须使用订单文件，禁止使用科目表，答案事实正确 |
| KB-004 | P0 | 多知识库数据隔离 | 同名或相似文档不会跨未绑定知识库命中 |
| KB-005 | P1 | 删除文件/知识库后的清理 | 检索、列表、对象存储和索引均不再残留 |
| KB-006 | P1 | 大型表格分段检索与续查 | 表头识别、分段结果和续查游标不跳错文档 |

| --- | --- | --- | --- |

## 7. 最近会话（4）

| ID | 优先级 | 场景 | 核心判定 |
| --- | --- | --- | --- |
| CONV-001 | P0 | 会话创建与最近排序 | 新消息更新顺序，列表与数据库一致 |
| CONV-002 | P0 | 重新打开并继续会话 | 消息、知识库/Skill范围和上下文正确恢复 |
| CONV-003 | P1 | 重命名与分页游标 | 名称持久化，分页无重复、遗漏和顺序漂移 |
| CONV-004 | P1 | 删除与重复记录防护 | 删除后不可访问，同一会话不产生多条最近记录 |

## 8. 套件划分

- `spark-x-agent-conversation-p0`：开发期可独立验收的 `CONV-001` 纵向切片；完成核心冒烟后仍保留为快速诊断套件；
- `spark-x-agent-tools-p0`：`TOOL-001/002` 内置只读工具目录、调用、结果回填、历史证据与清理闭环；
- `spark-x-agent-core-smoke`：所有 P0 中每个模块至少一个主路径，目标 10～12 个案例；
- `spark-x-agent-full-regression`：全部 32 个案例；
- 每个模块独立套件：聊天、工具、知识库、Skill、MCP、自动任务、最近会话；
- `spark-x-agent-real-model-canary`：真实模型多次运行案例；
- `spark-x-agent-deterministic-contract`：固定 Provider 和结构化契约案例。

## 9. 数据与证据要求

- CRUD 场景使用每次运行唯一前缀并登记所有资源；
- 知识库案例使用平台管理的固定测试文件资产，不引用个人临时文件；
- 每个 P0 失败至少保留结构化请求、关键日志和页面/工具证据中的一种；
- TOOL、KB、SKILL、MCP 场景尽可能采集工具清单、参数和结果；
- 真实模型案例同时保存每次重复的独立结果，不能只保留汇总百分比。

## 10. 当前实现检查点

`CONV-001`、`CHAT-001` 与 `TOOL-001/002` 已具备用例定义和受信任适配器执行闭环。CONV 覆盖创建会话、
最近排序和清理；CHAT 覆盖真实模型 SSE 终态、回答哈希、历史持久化一致性和清理；TOOL 覆盖普通用户工具
目录的凭据边界、管理员目录的只读风险策略、单次 `builtin-demo__calculator` 参数与结果、结果进入最终回复，
以及消息历史和公开执行轨迹与流式证据的 SHA-256 关联。会话型案例都登记资源台账，普通 `finally` 与 Worker
中断后的独立补偿共用同一删除动作。测试环境资产由
`scripts/provision-spark-x-agent-conversation-p0.ts` 幂等创建；脚本同时维护 CONV、TOOL 诊断套件和当前含四条
案例的 `spark-x-agent-core-smoke`，从文件或标准输入读取管理员密码，只向平台密钥库提交且不打印密钥。
已配置环境可设置 `SPARK_X_AGENT_USE_EXISTING_SECRETS=true`，此时脚本不读取也不更新密钥，仅复用平台密钥库
中已有的引用值，适合发布后无人值守回归。
当前进度为核心冒烟 4/10～12；仍以跨七个模块的 P0 全部落地为完成条件。
