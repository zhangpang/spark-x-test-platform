# MVP 验收清单

标记为“必须”的条目全部通过后，MVP 才可宣布完成。验收证据必须绑定具体平台版本和运行 ID。

## 1. 独立性与可部署性

- [ ] 必须：平台使用独立仓库、数据库、Redis和MinIO，不读取星火Agent内部数据库作为平台事实来源。
- [ ] 必须：在干净服务器通过Docker Compose可重复部署、升级和回滚。
- [ ] 必须：平台自身发布不依赖被测系统在线。
- [ ] 必须：API、调度器、Worker和存储健康状态可独立诊断。

## 2. 测试资产

- [ ] 必须：页面可以创建、保存草稿、静态校验、发布、停用和归档用例。
- [ ] 必须：发布版本不可修改；回滚生成新草稿，不改变历史。
- [ ] 必须：用例支持顺序、条件、受限`foreach`、公共步骤、数据集和`finally`。
- [ ] 必须：套件可复用用例，运行创建后固定所有用例及依赖版本。
- [ ] 必须：用例和公共步骤可导入导出，重装后可从备份恢复。
- [ ] 必须：页面无法提交任意可执行代码。

## 3. 执行与判定

- [ ] 必须：支持Chromium、HTTP、MCP、等待/轮询、JSON、变量和只读数据库动作。
- [ ] 必须：步骤、用例和运行各自具有超时；取消能传播到执行器。
- [ ] 必须：用例在通过、失败、取消和超时后都进入清理。
- [ ] 必须：第一次失败证据不被诊断重试覆盖；重试通过标记`flaky`。
- [ ] 必须：产品、脚本、环境、基础设施、不稳定、取消和跳过可以分别统计。
- [ ] 必须：环境或基础设施不可用不会被报告为产品通过或产品失败。
- [ ] 必须：每次运行记录用例版本、环境快照、被测版本、Worker镜像和适配器版本。

## 4. 隔离与故障恢复

- [ ] 必须：每次运行使用唯一`run_id`，创建资源进入副作用登记。
- [ ] 必须：资源锁防止不能隔离的账号或业务对象被并发修改。
- [ ] 必须：Worker失联后运行进入中断状态，不盲目重跑有写操作的案例。
- [ ] 必须：清理失败产生补偿任务，并且不覆盖原始失败。
- [ ] 必须：重复触发使用相同幂等键时只生成一个运行。
- [ ] 必须：长期运行中不存在永不释放的任务租约或资源锁。

## 5. 安全与审计

- [ ] 必须：所有外部请求和重定向目标经过环境白名单校验。
- [ ] 必须：云元数据、环回和未登记内网目标无法从用例访问。
- [ ] 必须：密钥只以引用出现，API不会返回明文，日志和附件完成脱敏。
- [ ] 必须：数据库查询连接只读，限制单语句、超时和最大行数。
- [ ] 必须：危险动作只能操作本次运行创建或显式登记的测试资源。
- [ ] 必须：匿名操作仍记录来源IP、请求ID、时间和修改版本。
- [ ] 必须：第一版所有服务限制在受控内网，Redis、MinIO管理端和Worker接口不暴露公网。

## 6. 星火 Agent 首个适配器

- [ ] 必须：只接入测试环境`192.168.110.136`，不使用阿里云证据替代。
- [ ] 必须：交付 [`spark-x-agent-case-catalog.md`](spark-x-agent-case-catalog.md) 中的32个P0/P1案例。
- [ ] 必须：聊天、工具、知识库、Skill、MCP、自动任务和最近会话都有独立套件。
- [ ] 必须：确定性契约套件和真实模型Canary分开统计。
- [ ] 必须：真实模型普通案例默认3次至少2次通过，硬约束每次都通过。
- [ ] 必须：B2C订单案例可以稳定识别订单文件为正确证据、科目表为禁止证据。
- [ ] 必须：知识库、Skill、MCP和自动任务CRUD案例执行后无残留测试数据。
- [ ] 必须：每个P0失败能下钻到日志、截图、Trace或结构化工具证据。

## 7. 页面体验

- [ ] 必须：八个MVP页面均可通过导航访问，并有加载、空、错误状态。
- [ ] 必须：用例编辑器能定位Schema和发布错误到具体步骤/字段。
- [ ] 必须：运行中心实时展示进度，断线后能从最后事件续接。
- [ ] 必须：运行详情展示首次失败、重试结果和清理结果三个独立维度。
- [ ] 必须：运行确认页明确环境、被测版本、用例数量和最高动作等级。

## 8. 调度与发布门禁

- [ ] 必须：支持页面一键、定时、API/Webhook和发布后触发。
- [ ] 必须：定时计划显式使用IANA时区并正确计算下一次触发。
- [ ] 必须：发布冒烟优先于全量和巡检，且至少预留一个高优先级执行槽。
- [ ] 必须：冒烟结果可返回`passed|blocked|inconclusive`、运行ID、失败摘要和报告地址。
- [ ] 必须：回调目标预先登记，不能由用例提供任意URL。

## 9. 容量、保留与恢复

- [ ] 必须：支持不超过50个内部使用者、5,000个用例和20个排队/执行任务的目标容量。
- [ ] 必须：浏览器实际并发通过测试机压测确定，并设置系统/环境配额。
- [ ] 必须：成功附件默认保留30天，失败附件180天，锁定运行不自动删除。
- [ ] 必须：每日备份PostgreSQL核心资产并验证校验结果。
- [ ] 必须：从备份恢复后，用例版本、套件和运行摘要保持一致。

## 10. 平台自身质量

- [ ] 必须：状态机、租约、资源锁、变量、脱敏、超时、清理和适配器协议具有自动化测试。
- [ ] 必须：GitHub Actions在不访问内网的前提下完成平台单元、契约、构建和无环境E2E测试。
- [ ] 必须：执行器和适配器依赖锁定，运行期间不动态安装依赖。
- [ ] 必须：OpenAPI、JSON Schema、数据库迁移和适配器清单在CI中自动校验。

## 11. MVP最终演练

验收人员从全新部署开始，完成以下闭环：

1. 恢复或导入星火Agent测试资产；
2. 执行测试环境健康检查；
3. 一键运行核心冒烟和全量回归；
4. 查看一个通过案例、一个产品失败和一个环境失败的完整证据；
5. 人工终止Worker，确认任务中断和补偿清理；
6. 由发布平台API触发冒烟并读取门禁结果；
7. 修改、校验、发布、比较并回滚一个用例；
8. 备份后重装平台，恢复测试资产并再次运行核心冒烟。
