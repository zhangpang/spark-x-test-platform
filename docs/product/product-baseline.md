# MVP 产品范围基线

## 1. 产品定位

星火自动化测试平台是公司内部自托管的通用自动化回归控制面。它提供统一的测试资产、执行编排、证据采集、失败分类和发布门禁能力，并通过系统适配器扩展业务动作。

第一版没有用户登录，但仍是受控内网服务，不是公开匿名服务。

## 2. 目标

1. 让维护人员在页面中创建、发布、停用、归档、比较和回滚自动化业务用例。
2. 让执行人员选择环境和套件后一键回归，并实时查看进度和证据。
3. 让发布平台通过 API/Webhook 触发冒烟或全量回归，获得可审计的门禁结果。
4. 让系统通过标准浏览器/HTTP 能力零改造接入，并通过可选适配器获得业务动作及结构化证据。
5. 让 AI 系统的工具选择、参数、证据来源、业务事实和副作用得到可重复判定。
6. 首先证明星火 Agent 七个重点模块可稳定回归，再扩展到其他系统。

## 3. 使用者与主要任务

第一版所有页面操作记为 `anonymous`，但产品仍按职责描述使用场景：

| 使用者职责 | 主要任务 |
| --- | --- |
| 用例维护 | 创建用例、公共步骤和数据集，调试、发布、回滚、导入导出 |
| 回归执行 | 选择环境和套件，一键执行，取消任务，重试失败迭代 |
| 发布控制 | 触发冒烟，读取质量门禁状态和报告地址 |
| 故障分析 | 查看步骤日志、截图、Trace、请求响应、工具调用及环境快照 |
| 平台维护 | 登记系统和环境，配置 Worker、适配器、密钥引用及保留策略 |

## 4. 测试资产层级

```text
系统
└── 模块
    └── 用例（不可变版本）
        ├── 数据集迭代
        ├── Fixture / 公共步骤
        ├── 执行步骤
        ├── 断言
        └── finally 清理

套件 ──引用──> 一个或多个已发布用例
计划 ──触发──> 套件 + 环境 + 运行参数
```

同一用例可以加入多个套件。套件在运行创建时解析并固定所有用例版本，后续修改不得改变历史运行。

## 5. 用例生命周期

| 状态 | 可编辑 | 可手工运行 | 可被计划/发布门禁运行 |
| --- | --- | --- | --- |
| `draft` | 是 | 是 | 否 |
| `published` | 通过新版本修改 | 是 | 是 |
| `disabled` | 通过新版本修改 | 否 | 否 |
| `archived` | 否 | 否 | 否 |

发布前必须通过 Schema、变量、密钥引用、动作能力、适配器兼容性、环境权限和清理规则静态检查。

## 6. 触发方式

- 页面手工运行；
- 定时计划，显式保存 IANA 时区，默认 `Asia/Shanghai`；
- API/Webhook 调用；
- 发布平台部署后触发冒烟或全量回归；
- 失败案例、数据集迭代的人工重试。

队列优先级依次为发布门禁冒烟、人工冒烟、故障复现、全量回归、定时巡检。不得通过抢占中断已产生写操作的案例。

## 7. 结果语义

单次用例迭代使用以下终态：

- `passed`
- `product_failed`
- `test_failed`
- `environment_failed`
- `infrastructure_failed`
- `flaky`
- `cancelled`
- `skipped`

第一次失败证据永久属于本次运行。诊断重试成功后结果为 `flaky`，不能覆盖为普通通过。清理失败作为独立维度展示，不覆盖原始结果。

## 8. 星火 Agent 首批范围

首个系统为星火 Agent，首个环境为测试环境 `192.168.110.136`。第一版交付 32 个 P0/P1 自动化用例：

| 模块 | 必须覆盖的主路径 |
| --- | --- |
| 聊天 | 新会话、流式回答、停止、重试、续接、错误展示、上下文保持 |
| 工具调用 | 工具发现、工具选择、参数绑定、执行结果映射、失败恢复、最终回答 |
| 知识库维护与使用 | 创建、上传、解析/索引就绪、绑定、检索范围、命中文档、引用、删除清理 |
| Skill | 新增、修改、停用、删除、会话注入、能力调用、版本生效 |
| MCP | 新增、修改、停用、删除、连接、工具发现、Schema、调用、断线处理 |
| 自动任务 | 新增、修改、停用、删除、立即触发、计划触发、幂等、结果投递 |
| 最近会话 | 创建、排序、重命名、分页、读取、删除、重复防护、续接 |

知识库 P0 案例必须包含“B2C 订单文件准确检索”：准备科目表和 B2C 订单文件，要求使用订单文件、禁止把科目表作为答案证据，并验证最终订单事实。

## 9. AI 测试策略

### 9.1 确定性回归

使用固定 Provider 响应、结构化输入或模拟模型，验证工具注入、参数绑定、权限、调用循环、结果映射和副作用。确定性 P0 案例作为强制发布门禁。

### 9.2 真实模型回归

真实模型案例默认执行 3 次，普通案例至少 2 次通过；安全、权限、错误文档和错误写操作等硬约束必须 3 次全部满足。用例可覆盖默认次数和门槛。

主要断言：

- 预期及禁止调用的工具；
- 规范化后的关键参数；
- 预期及禁止命中的文档；
- 引用和证据范围；
- 最终回答的关键业务事实；
- 不允许产生的写操作。

语义 Judge 只作为辅助结论，模型、提示词和版本都需要记录。Judge 不可用不直接判定产品失败。

## 10. 成功指标

- 七个重点模块均具备可重复运行的 P0/P1 案例；
- 一键执行后无需人工拼接日志即可定位到失败步骤；
- 所有运行均可追溯到用例版本、被测版本和环境快照；
- CRUD 用例完成后不存在未登记残留数据；
- 环境、测试脚本、基础设施和产品失败可以分开统计；
- 发布平台可以机器读取冒烟门禁结果；
- 平台重装后用例资产可以从备份恢复。

## 11. 第一版非目标

- 用户登录、角色权限和审批；
- Worker 身份认证及跨公网执行；
- 人工测试执行、评审和签字；
- 页面上传或执行任意代码；
- Kubernetes 部署；
- 完整缺陷管理；
- 全局像素级视觉门禁；
- 复杂统计大屏；
- 阿里云或生产环境回归；
- 商业 SaaS 的租户注册、计费和配额销售。

数据模型为用户认证、人工用例和多组织预留扩展空间，但这些能力不得进入 MVP 隐性范围。
